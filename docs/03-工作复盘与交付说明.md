## 二、关键教训（最有价值的部分）

### 2.1 「两个各自合理的设计，碰在一起才是 bug」

`Invoke`（同步切 UI 线程）和 `Wait()`（同步占线程）**单看都没问题**，
但调用链串起来就是死锁。这类问题**看单个文件永远发现不了**，
必须把调用链串起来看。审查时不能只逐文件看，要问"谁在等谁"。

### 2.2 「编译通过 + 页面自检通过 ≠ 程序能用」

`{StaticResource}` 键名写错，编译期不报错；`--smoke` 只遍历导航页，
**对话框不在导航里**，所以出现了最坑的组合：

> 程序能启动 → 8 页自检全绿 → 188 个测试全过 → **一点「切换身份」就崩**

**对策**：把"自检覆盖不到的东西"补进自检。现在 `--smoke` 会实例化全部对话框。
**并且验证过这个自检真的能拦住**——故意写错键名，退出码立刻变 1。

### 2.3 「状态类 bug 要靠调命令 + 断言状态，不能靠读代码」

"手动页无法切换轴"这个问题，我把相关代码来回读了三遍都没看出来。
最后给 `--smoke` 加了个交互自检（调 `SelectAxisCommand` 再断言 `IsSelected`），
**一次就精确暴露**：切换后旧轴仍处于选中态。

结论：与其反复读代码，不如写一行会失败的断言。

### 2.4 重写文件是高风险操作

`OnSelectedAxisChanged` 就是这么丢的——我重写 `ManualViewModel` 时，
新版本没把旧版本的某个 `partial` 回调带过来。

**教训**：重写整个文件时，要逐条比对旧版本有哪些成员，
尤其是**看不出用途的 `partial void` 回调**——它们不报错、不影响编译，静默失效。

### 2.5 「防呆要做在服务层，不能只做在界面」

气缸绑定地址必须是 M 区这条约束：
- 界面层：编辑器只让填 M 区
- **服务层**：`解析设备中继()` 再解析一次地址类型，非 M 区直接抛异常

即使有人手工改错 JSON，也不会执行到 Y 点。**界面是给正常用的，服务层是兜底的。**

## 四、给后续接手者的提示

### 4.1 开发环境

```bash
source ~/.workbuddy/dotnet-env.sh    # 必须！否则 NuGet 报 path1 为 null
dotnet build PlcHmi.slnx             # 解决方案是 .slnx 不是 .sln
```

### 4.2 改完必须跑的四道验证

```bash
dotnet build PlcHmi.slnx              # 0 警告 0 错误
dotnet test PlcHmi.slnx               # 188 个测试
dist/PlcHmi.App.exe --smoke           # 8 页 + 3 对话框 + 交互自检
dist/PlcHmi.App.exe --shots <dir>     # 出图确认界面
```

### 4.3 发布

```bash
dotnet publish src/PlcHmi.App -c Release -r win-x64 --self-contained true \
  -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true \
  -p:EnableCompressionInSingleFile=true -p:DebugType=none -o dist
```

### 4.4 三条不能破的规矩

1. **UI 线程切换用 `BeginInvoke`，禁止 `Invoke`**；同步等待用 `await`，禁止 `SemaphoreSlim.Wait()`
2. **XAML 资源键只能用 `Themes/*.xaml` 里已定义的**（字体 `UiFontFamily`、页面底色 `SurfaceAltBrush`）
3. **新增对话框要加进 `应用.验证对话框()`**，否则又会漏出"点开才崩"的问题
