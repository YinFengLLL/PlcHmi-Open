## 一、背景与目标

项目原本 C# 标识符为英文（`AlarmScanService` / `MapStatusWord`…），注释为中文。
本次把**自研代码**的以下标识符全部改为中文：

- 命名空间、类、接口、结构体、枚举、委托
- 事件、属性、字段、方法、参数、局部变量、常量

**不改的**：注释内容、文件名（`RecipeStore.cs` 等保持原名）、项目名/程序集名
（`PlcHmi.*` 是部署身份，不属于代码标识符）、XAML 资源键（`ButtonSuccess` 等样式键）。

**为什么做**：这是工控上位机模板项目，读者是现场工程师与继任维护者。
中文标识符让"代码里的名字"与"图纸、配置文件、界面上的名字"直接对上，
省掉一层脑内翻译，显著降低交接成本。

## 二、命名风格（固化为本项目规范）

| 对象 | 风格 | 示例 |
|---|---|---|
| 类型 / 方法 / 属性 / 事件 | 中文名词或动宾短语，不加空格 | `报警扫描服务`、`异步写入参数`、`连接状态文本` |
| 字段 / 局部变量 / 参数 | 中文名词 | `订单列表`、`当前用户` |
| 私有字段 | 下划线前缀 | `_连接状态文本` |
| 布尔值 | `是否…` / `有…` / `可…` 开头 | `是否启用`、`可编辑元件` |
| 集合 | `…列表` / `…集合` / `…表格` | `延迟集合`、`标签集合` |
| [ObservableProperty] 字段 | `_中文名`，生成属性为 `中文名` | `_是否选中` → `是否选中` |

**保留英文/拉丁的例外（刻意，不是漏改）**：

| 类别 | 例子 | 理由 |
|---|---|---|
| 领域专名 | `PLC`、`CSV`、`JSON`、`Modbus`、`汇川`（Inovance→汇川）、`FluentModbusTCP客户端` | 行业通名，硬翻反而难读 |
| 设备约定名 | `软元素.X/Y/M/D/SM/SD/MW`、`标签数据类型.UInt16/Float32`、`轴标识.X/Y/Z/R` | 与 PLC 侧图纸、配置 JSON 字符串一一对应，改了就断 |
| 框架约定成员 | `OnStartup`、`Dispose`、`IHostedService.StartAsync`、`Convert/ConvertBack` | override / 接口实现，改名即破坏契约 |
| 源生成器钩子参数 | `partial void On是否选中Changed(bool value)` 的 `value` | CommunityToolkit 生成的声明用 `value`，实现参数必须同名（否则 CS8826） |
| XAML 资源键 / 文件名 | `ButtonSuccess`、`RecipeStore.cs`、`PlcHmi.App.exe` | 资源键与部署身份不在改造范围 |

## 三、方法与工具链

**核心决策：不用文本替换，用 Roslyn 语义级重命名。**
项目里大量存在"自研成员与框架成员同名"的情况（`报警条目.消息` vs `Exception.Message`），
按名字替换必炸；只有把每个标识符解析到**符号**，才能精确区分"改谁、不改谁"。

执行链路（工具为一次性脚手架，用完已删）：

1. **inventory** —— Roslyn 编译全解决方案（含 WPF `.g.cs` 生成码与隐式 using），
   导出全部自研符号：种类 / 声明位置 / 容器 / 注释 / 源码行
2. **compose + overrides** —— 词素级自动组词生成草稿映射（≈2400 条），人工复核修正
3. **apply** —— 按映射表逐符号改写，保留 BOM / 换行 / 格式；文档注释里 `cref`/`paramref` 同步
4. **配套同步** —— XAML（x:Class / clr-namespace / 绑定路径 / x:Name）、`config/*.json` 键
5. **四道校验**（见 §5）

## 五、坑点总结（本次改造最值钱的部分）

### 🔴 P1 · 编译器查不出的问题，占了坑点的大半

1. **XAML 绑定是运行时解析的**。C# 属性/命令改名后，`{Binding DataContext.AcknowledgeCommand}`
   照样编译通过、326 个测试全绿——但界面上的按钮已经是死的。
   **教训**：改名后必须静态审计全部绑定路径 vs 符号清单（本次审计出 36 处残留 + 2 处错名）。
   `IsSelected`/`IsEnabled` 还要区分是框架属性（`ListBoxItem.IsSelected`）还是自研同名属性，不能一刀切。

2. **改名合并引入 lambda 遮蔽**。两个不同的英文名（如 `client` 与 `c`）映射到同一个中文名
   （`客户端`）后，lambda 参数与外围变量同名——编译不报错、测试不红，
   但 `FindIndex(x => Equals(x.Id, x.Id))` 这类语义漂移随时发生。
   **教训**：改完必须跑"遮蔽检查"并与改造前基线对比；新增项按声明位置用 spotMap 精确消歧。

3. **语义等价校验是对付静默破坏的兜底**。以 git HEAD 为参照双编译，
   逐标识符比较"解析到的声明位置"是否一致。368 处报告按文件行数核对后全部是伪影
   （长中文名导致换行重排、补 using 引起的行错位），真实差异为零。
   **教训**：校验报告本身也要人审，不能只看总数。

### 🔴 P2 · 跨文件契约：改名 = 契约变更

4. **配置 JSON 键与属性名大小写不敏感匹配**。属性 `PLC`→`PLC连接`，`appsettings.json`
   的键必须同步改，否则现场启动就是一排空配置（且是静默降级，见 R3 红线）。

5. **枚举以字符串持久化**。`标签数据类型.UInt16`、`轴标识.X` 这类成员改名，
   会让所有存量 JSON 解析失败。本次**刻意保留**设备约定名的枚举成员不改，
   根本不存在"顺手全改"的空间——每个枚举都要单独决策。

6. **源生成器生成名是隐式契约**。`[RelayCommand]` 生成 `确认Command` 属性（XAML 在用）、
   `[ObservableProperty]` 生成属性 + `OnXChanged(value)` 部分方法（实现参数名必须与生成声明一致，
   否则 CS8826，且 `value` 是上下文关键字、改名工具必须跳过）。

### 🟡 P3 · 工具与流程

7. **字符串字面量会被词法替换误伤**：`\bPLC\b` 把错误提示文案里的
   "由 PLC 程序决定何时驱动 Y 输出"改成了"由 PLC地址 程序…"。替换必须区分代码与字符串/注释。

8. **`\b` 在 CJK 字符旁的行为是双刃剑**：`配方CSV编解码器` 里的 `CSV` 因中文接续不构成词边界
   （保护了它），但 `CSV[CSV.IndexOf(...)]` 这种索引访问就漏改了（坑）。逐文件 diff 复核不可省。

9. **全大写缩写（JSON/CSV/PLC/UI）是检查盲区**：它们看起来"像可以接受"，容易漏出映射表。
   本次约定：局部变量加中文后缀（`JSON文本`/`CSV文本`），属性/类型名中文化（`PLC连接`/`界面`）。

10. **自动组词会产出怪词**：`WriteHuman` → 「写入人为」（本意是"人工手写文件的风格"）。
    词法组合只是草稿，**必须人工过一遍全部映射**，配 overrides 修正表。

11. **改完工具必须重建再跑**：`--no-build` 跑的是旧二进制，缺了关键字跳过逻辑，
    把框架的 `Serilog.Log`、`Microsoft.Extensions.Hosting.Host` 改成了 `日志`/`主机`
    （54 处，按日志精确回滚并把 `Log`/`Host` 加入外部标识符保护名单）。

12. **Roslyn 扫描编译的引用陷阱**：WindowsDesktop 引用包要放在 NETCore 之前、
    排除自包含发布目录（CS1705）、排除项目自身输出（歧义）、必须并入 `.g.cs` 与 GlobalUsings。
    扫描编译剩 ~300 个错误是**缺失源生成器**所致，属预期基线，别被吓到。

13. **历史文档会集体过期**：所有 MD 里的 `MainViewModel.BuildNavigation()`、
    `DeviceService.MapStatusWord()` 这类引用在改名后全部失效。
    本次已同步修订 01/02/03/04/05 与审查文档；**历史快照类章节（如 04 §1）保留原文、加注说明**。

## 六、对后续开发的要求（长期有效）

1. **新增代码一律用中文标识符**，风格按 §2；英文只允许出现在 §2 例外清单里。
2. **框架约定成员保持英文名**：override / 接口实现 / 生成器钩子参数，改了就是破坏契约。
3. **改名类 PR 属于跨文件契约变更**：
   - 改属性名 → 同步 `config/*.json` 键
   - 改枚举成员 → 全库搜该枚举的字符串用法（含 XAML、JSON、日志文案）
   - 改命令/属性名 → 同步 XAML 绑定路径
4. **审查时新增两条口径**（已并入 04 文档与检查清单）：
   - 新标识符不符合 §2 风格 → 🟡
   - 改名漏同步绑定/配置/枚举字符串 → 🔴（按破坏契约处理）
5. 门禁命令不变：`pwsh tools/verify.ps1`（或 `tools/verify.sh`）。
