## 一、项目概览

### 1.1 目标

基于 **C# / WPF (.NET 10)** 的通用工控上位机模板，通过 **Modbus TCP** 与 **汇川 (Inovance) PLC** 通信，
实现接近触控屏 (HMI) 的操作体验。

### 1.2 核心设计理念

**一切配置化。** 程序本身不知道"X0 是什么""机种 3 的速度是多少"——
这些全部来自 `config/` 下的 9 个 JSON 文件。换设备时只改配置，不动代码。

这条理念贯穿全项目：

| 配置化对象 | 配置文件 | 效果 |
|---|---|---|
| 业务点位 | `tags.json` | 换 PLC 地址不用改代码 |
| IO 点位含义 | `io-points.json` | 现场工程师自己填 X0 是什么 |
| 机种参数项 | `recipe-config.json` | 加参数（延时、速度）只改 JSON |
| 机种数据 | `recipes.json` | 20 个机种的参数与点表 |
| 全部基址 | `recipe-config.json` | 换 PLC 内存规划不动代码 |
| 手动页元件 | `manual-widgets.json` | 管理员在界面上增删元件 |

### 1.3 功能范围

| 页面 | 功能 |
|---|---|
| 运行监控 | 启停复位、报警清除（M799）、状态、节拍、产量、实时监控；急停由物理按钮负责，上位机不提供急停按钮 |
| 参数设置 | 四轴定位速度 / 手动速度，下发与留底 |
| 示教 | 100 个定位点（10 面 × 10 点）的示教与下发 |
| 机种管理 | 机种切换、命名、CSV 导入导出、一致性校验 |
| 手动调试 | 气缸手动、四轴点动（配置驱动 + 手动使能联锁） |
| IO 点位 | X/Y 八进制分组监控，含义可编辑 |
| 报警记录 | 报警列表与确认 |
| 系统设置 | 连接配置、参数、日志 |

## 四、通信层设计

### 4.1 汇川软元件 → Modbus 地址映射

| 软元件 | 进制 | Modbus 起始 | 十进制 | 功能码 |
|---|---|---|---|---|
| M0–M7999 | 十进制 | 0x0000 | 0 | FC01 线圈 |
| B0–B32767 | 十进制 | 0x3000 | 12288 | FC01 线圈 |
| S0–S4095 | 十进制 | 0xE000 | 57344 | FC01 线圈 |
| **X0–X1777** | **八进制** | 0xF800 | **63488** | **FC02 离散输入**（物理输入） |
| **Y0–Y1777** | **八进制** | 0xFC00 | **64512** | FC01 线圈（物理输出） |
| D0–D7999 | 十进制 | 0x0000 | 0 | FC03 保持寄存器 |
| R0–R32767 | 十进制 | 0x3000 | 12288 | FC03 保持寄存器 |

> **X 与 Y 的功能码分工（2026-10-17 现场第二次报障后修正）**：X 是**物理输入** →
> 离散输入表（FC02）；Y 是**输出** → 线圈表（FC01）。此前 X 被配在线圈表，等于用 FC01
> 读输入区，现场表现是"Y 一直正确、X（X0–X7 / X10–X17）一直对不上"——连接正常、无异常、
> 无告警，只是读到了同一段地址上无关的位。机型把 X 放在线圈表时仍可自愈：
> 读不通（抛异常）会回退、读全 0 而另一位区有信号会切换，且只切一次。
> 拿不准时用 IO 页的「IO 通信诊断」把两个功能码的原始读数并排看一眼。

**换算公式**：`Modbus地址 = 区起始地址 + 软元件序号`（X/Y 的序号按**八进制**解析）

- `X10` → 63488 + 8 = **63496**（不是 +10）
- `Y10` → 64512 + 8 = **64520**
- `M100` → 100；`D100` → 100

### 4.2 32 位数据字序：CDAB

汇川默认 **CDAB（低字在前）**。32 位值先按大端排成 4 字节 `A B C D`，
`AB` 是高字、`CD` 是低字，寄存器顺序为 `[CD, AB]`。

**实测验证向量**（Float32，已用于单元测试）：

| 设定值 | IEEE 754 | 高字 AB | 低字 CD | 寄存器顺序 |
|---|---|---|---|---|
| 120.00 | `0x42F00000` | `0x42F0` | `0x0000` | Dn=`0x0000`, Dn+1=`0x42F0` |
| 250.50 | `0x437A8000` | `0x437A` | `0x8000` | Dn=`0x8000`, Dn+1=`0x437A` |
| −999.99 | `0xC479FF5C` | `0xC479` | `0xFF5C` | Dn=`0xFF5C`, Dn+1=`0xC479` |
| 9999.99 | `0x461C3FF6` | `0x461C` | `0x3FF6` | Dn=`0x3FF6`, Dn+1=`0x461C` |

> **关键事实**：32 位浮点与 32 位整数使用**完全相同**的拆分规则（都是低字在前），
> 所以 `寄存器编解码器` 一套框架同时支持两者。
>
> **字序写反的后果**：`120.00` → `0.00`（看起来像"轴没动"，极难排查）；`9999.99` → `1.92`。

### 4.3 通信层组件

| 组件 | 职责 |
|---|---|
| `汇川地址解析器` | 软元件符号（`D100`/`X10`）→ Modbus 地址 + 数据区 |
| `寄存器编解码器` | 位/16 位/32 位/浮点的编解码，含字序处理 |
| `FluentModbusTCP客户端` | `Modbus客户端接口` 实现，`SemaphoreSlim` 串行化请求 |
| `OPCUA客户端` | `Modbus客户端接口` 的 OPC UA 实现：会话管理 + “区域+地址 → NodeId”读写翻译 |
| `NodeId推导器` | 软元件符号 → OPC UA NodeId（默认 `D100 → ns=2;s=D100`），与基址表共用反解逻辑 |
| `仿真OPCUA客户端` | OPC UA 模拟器，与 `仿真Modbus客户端` 共享虚拟 PLC 内存 |
| `连接管理器` | 连接生命周期、心跳保活、断线指数退避重连 |
| `虚拟PLC设备` | **内置 Modbus 从站模拟器**，无 PLC 也能跑通全流程 |
| `示教地址映射` | 示教点表地址计算（按轴分区） |

### 4.4 通信层硬约束

| 约束 | 数值 | 来源 |
|---|---|---|
| 单次读寄存器上限 | 123 | 汇川协议限制 |
| 本模板保守取值 | **100** | 留安全余量 |
| Modbus TCP 客户端数 | **只开 1 个** | H5U 默认上限 8，留余量给触摸屏 |
| 会话号 | 从 **1** 开始 | 部分 PLC 不接受 0 |

### 4.5 通讯协议切换（Modbus TCP / OPC UA）

**两种切换方式**：① 界面「系统设置 → 连接参数编辑（管理员）→ 通讯模式」下拉，保存时二次确认
并写入 `appsettings.json`，**重启程序生效**；② 直接改 `appsettings.json → PLC连接.通讯协议`。
OPC UA 端口 / 命名空间索引可在同一张卡里改（端口与命名空间对当前会话即时生效，协议切换需重启）。

`appsettings.json → PLC连接.通讯协议` 决定 DI 装配哪套客户端实现，**业务层零感知**：

| 通讯协议 | 使用模拟器 | 注入的 `Modbus客户端接口` 实现 |
|---|---|---|
| ModbusTCP（缺省） | false | `FluentModbusTCP客户端` |
| ModbusTCP（缺省） | true | `仿真Modbus客户端` |
| OPCUA | false | `OPCUA客户端` |
| OPCUA | true | `仿真OPCUA客户端` |

- **旧配置无需迁移**：缺省回退 Modbus TCP；`PLC连接设置服务` 落盘时原样带过协议字段。
- **语义翻译**：OPC UA 客户端与 Modbus 客户端共用同一契约——线圈/离散输入读 Bool 节点，
  保持/输入寄存器读 UInt16 节点；连续地址先按软元件反解切分（M/B/S/X/Y 基址互不相连），
  每段合并为一次批量请求。字序处理仍由 `寄存器编解码器` 在业务侧完成（红线 R1 不变）。
- **NodeId 推导**：`NodeId推导器` 把 Modbus 地址经 `汇川地址解析器.反解` 还原为软元件符号
  （X/Y 八进制还原），再按 `OPCUA节点格式` 模板拼 NodeId（默认 `ns=2;s=D100`）。
- **心跳兼容**：连接管理器“读 D0 保活”在 OPC UA 模式下自动翻译为读 D0 节点，
  重连状态机零修改。协议与模拟器为 DI 定型参数，运行期修改无效，需重启程序。
- **安全**：默认安全策略 None + 自动信任服务端证书（PLC 自签证书现场常态）；
  填写 `OPCUA用户名`/`OPCUA密码` 即切换为用户名口令鉴权。

### 4.6 汇川变量表导入与变量符号绑定

管理员在系统设置页导入 AutoShop 变量表 CSV（`序号,变量名,数据类型,…,软元件地址`）→
解析（REAL→Float32 / INT→Int16 / BOOL→布尔等，跳过结构体头行）→ 原子落盘 `config/variables.json`。

**绑定语义**（轴参数区 / 延时区 / 气缸区配置条目可选 `变量` 字段）：

- 选中变量后自动回填 `地址` 与数据类型——下游服务继续按地址工作（Modbus 零改动）；
- **OPC UA 模式**：绑定点位的地址段整段匹配到变量时，直接以变量名作 NodeId
  （模板 `OPCUA变量格式`，默认 `ns=2;s=X轴命令.b_轴使能`），多字变量经寄存器编解码器做类型↔寄存器转换（红线 R1）；
- **失效降级**：变量表缺失 / 变量改名时保留原地址并经配置健康登记示警，禁止无声降级；
- **界面显示规则**（`绑定显示`）：OPC UA 模式 + 已绑定变量 → 手动页元件、延时/按钮表、
  轴速度行的地址列直接显示<b>变量名</b>（物理地址不参与寻址）；Modbus 模式或未绑定 → 显示软元件地址；
- **字.位限制**：`D1210.0` 形式的 BOOL 变量无法按 Modbus 寻址（小型 PLC 解析器不支持字内位），
  绑定会被拒绝——建议 PLC 侧映射到 M 区或使用独立 BOOL 变量。

## 五、业务层设计

### 5.1 采集引擎

`轮询引擎` 按分组周期采集，核心优化：

1. **连续地址合并**：相邻点位合并为一次请求，减少往返
2. **变化检测**：值不变不推事件，避免 UI 空转
3. **分组周期**：Fast 100ms（状态/IO/轴位置）、Slow 500ms（产量/参数）、Event 1000ms（报警）

### 5.2 服务清单

| 服务 | 职责 |
|---|---|
| `标签值服务` | 实时值缓存与变化事件 |
| `设备服务` | 状态机、节拍、产量、启停命令 |
| `报警服务` | 报警产生、确认、历史缓冲 |
| `IO点位服务` | X/Y 点位状态，含反相处理 |
| `配方服务` | 机种切换、参数下发、CSV 导入导出 |
| `示教服务` | 示教点表读写、面启用、索引同步 |
| `配方存储` | `recipes.json` 的唯一内存真相（**单例**） |
| `手动控件服务` | 气缸与点动，含手动使能联锁 |
| `PLC运行期托管服务` | 随宿主生命周期启停，并做启动一致性校验 |

> **`配方存储` 为什么必须是单例**：`配方服务` 管参数、`示教服务` 管点表，
> 两者写同一个 `recipes.json`。若各自持一份内存副本，后保存的会把先保存的覆盖掉——
> 这是实施中实际踩到的坑。

## 七、PLC 地址规划（当前实现）

汇川小型 PLC D 区范围 `D0 – D7999`。

| 分区 | 地址 | 字数 | 说明 |
|---|---|---|---|
| 系统区 | D0 · D10 · D20 | — | 状态字 / 节拍 / 产量 |
| *报警位区* | *D500 – D510（事件）· D511 – D599（普通报警）* | 100 | 见 PLC 地址分配表；报警位区另有 D550 – D554 字位段 |
| **延时表专属区** | **D1000 – D1098** | 99 | 2026-10-16 起延时按 **DINT 占 2 字**，可放 50 条；地址必须间隔 2，服务层硬校验区间与重叠 |
| 生产监控量 | **D1100 – D1108** | 9 | 节拍 / 当前产量 / 目标产量 / 良品 / 不良品（运行监控页可改地址）|
| 生产监控量（工位计数） | **D1116** | 1 | 已锁附颗数（**INT**，16 位有符号）；主页面左下状态条读取 |
| *上位机预留段* | *D1117 – D1199* | 83 | 用途待定 |
| **轴参数区（轴 1–轴 6）** | **D1200 – D1799** | 600 | 每轴 100 字：轴 1 D1200–D1299 … 轴 6 D1700–D1799 |
| **轴参数允许区间** | **D1200 – D1799** | — | 定位速度 + 点动档位等轴参数只能落在此区间 |
| 轴定位速度（4 项） | **D1202 / D1302 / D1402 / D1502** | 8 | `X/Y/Z/R.LocateSpeed`，**Float32 各占 2 字**（各轴区偏移 2）|
| 轴当前位置（4 项） | **D1221 / D1321 / D1421 / D1521** | 8 | X/Y/Z/R 当前位置，**Float32** CDAB（各轴区偏移 21）|
| 点动速度档位（4 项） | **D1212 / D1312 / D1412 / D1512** | 4 | 每轴 1 字，写 1 低 / 2 中 / 3 高（各轴区偏移 12）|
| 点动方向命令位 | **D1210.2/.3 · D1310.2/.3 · D1410.2/.3 · D1510.2/.3** | 8 | D 字内位（偏移 10 的命令字第 2/3 位），上位机读-改-写整字 |
| 示教点表区 | **D2500 – D3299** | 800 | 按轴分区：X 2500 / Y 2700 / Z 2900 / R 3100 |
| 面启用标志 | **D3320 – D3329** | 10 | 每面 1 字，0=停用（默认）1=启用 |
| 机种与示教控制区 | **D3330 – D3339** | 10 | 机种号 / 机种总数 / 示教索引 / 当前面号 |
| 默认机种配方区 | **D2500 – D3499** | 1000 | 与示教点表区重叠段现由示教与机种控制使用 |
| 气缸区 | **D3500 – D3599** | 100 | 每缸 1 字，bit0–4 动作 / 置位到位 / 复位到位 / 置位报警 / 复位报警 |

> ⚠️ **2026-09-17 修订（按现场 PLC 地址分配表）**：
> 1. 轴参数区统一为 **D1200 – D1799**（轴 1–轴 6 各 100 字），定速 / 档位 / 位置 / 点动全部按表的偏移落位：
>    偏移 0 点动速度、2 定位速度、4 加减速度、10 命令字（位 0 使能 / 1 回原 / 2 正向点动 / 3 反向点动 / 4 定位请求）、
>    11 定位点字、12 手动速度档位、20 状态字、21 当前位置、23 轴故障码。
>    原 **D1500 – D1999 区间与 D1600/D1802 一类地址已作废**。
> 2. **点动方向改为 D 字内位**（汇川位打包：BOOL 占 D 的一位），上位机写命令走
>    「读整字 → 改位 → 写回」（Modbus 无写字内位功能码）；写通道串行化，与 PLC 并发写同字仍有竞态，需 PLC 侧配合。
> 3. 变量表导入的 D 字位条目（如 `D1210.0`）自本版起可寻址并参与绑定。
>
> ⚠️ **2026-09-12 修订（需求方确认）**：
> 1. **D1000–D1500 原先记为「PLC 公共区、禁止占用」，该规则已作废** —— PLC 侧已释放整段给上位机，
>    现划分为 D1000–D1099 延时专属区 + D1100–D1199 上位机预留段（V1.7 文档中的 D1100–D1500 表述已由 09-17 分配表取代）。
> 2. 参数项由 8 项精简为 **4 项定位速度**；`*.ManualSpeed` 已废弃，点动速度改由**档位寄存器**决定。
> 3. 参数类型由配置 `dataType` 声明（Float32 占 2 字）—— 此前代码硬编码 UInt16 且只写 1 个寄存器，
>    而地址连续，导致**后项低字踩前项高字**。改类型后地址必须间隔 2。
> 4. 延时表旧地址 D700–D702 已迁移到 **D1000–D1002**。
>
> ⚠️ **2026-10-16 修订（现场确认）**：
> 1. **延时改按 DINT（32 位整数毫秒，占 2 字、低字在前）下发**，上限 2147483.647 S（原 16 位毫秒只有 65.535 S）；
>    专属区上限相应收到 **D1098**，默认地址排成 D1000 / D1002 / D1004，服务层拒绝地址重叠。
>    升级时需 **PLC 侧同步改为按 32 位解析**。
> 2. 新增主页面左下状态条的三盏指示灯与「已锁附颗数」：三盏灯是 **M 区位**
>    （M490 / M491 / M492，FC01 读线圈，0=未完成 / 1=完成），颗数在 **D1116**（INT）。
>    地址由管理员在运行监控页「编辑地址」维护（点位定义在 `config/tags.json`）。

### M 区

| 地址 | 用途 |
|---|---|
| M200 – M202 | 启动 / 停止 / 复位命令 |
| M666 | 手动使能（打开持续置位 / 关闭持续复位） |
| M220 – M225 | 气缸 1–3 伸出 / 缩回 |
| ~~M230 – M237~~ | ~~四轴点动（正 / 反）~~ —— **2026-09-17 起点动改为轴参数区的 D 字内位**（D1210.2/.3 等），不再占用 M 区 |
| **M799** | **报警清除命令（脉冲写）**。**上位机不提供急停按钮**——急停必须由物理按钮实现，软件卡死或断线时按钮就失效了，不能进安全回路；上位机只负责把状态字 3（急停）显示出来 |
| **M5000 – M5099** | **参数页自定义按钮区**：置位 = 开启、复位 = 关闭（即写 M 区，不回读），工程师可操作；M5000 以下是系统保留段，避免自定义开关撞掉系统功能 |
| **M490 – M492** | **工位完成状态位（只读）**：锁附完成 / 点胶完成 / 加工完成，`0` = 未完成、`1` = 完成；主页面左下三盏指示灯读取（2026-10-16 现场要求，地址可在运行监控页改） |
| **M500 – M600** | **报警位区：101 个位，每位一条报警** |

> **手动页元件的绑定地址限制在 M 区**：气缸等元件只置位内部继电器（M），
> 由 PLC 程序决定何时驱动 Y 输出。上位机**不直接控制 Y 点**——
> 这是安全设计，避免上位机绕过 PLC 的联锁逻辑。

## 九、配方与示教（摘要）

详见 [02-参数-示教-机种需求设计](02-参数-示教-机种需求设计.md)。

**核心要点**

- **分工**：上位机 `recipes.json` 是主存（全部机种）；PLC 只放**当前机种生效**的一份
- **示教点表随机种**（每机种 100 点）、**参数不随机种**（PLC 里只有 8 字）
- **写入时机硬约束**：参数只在「下发」或「切换机种」时写；示教点只在「示教」或「下发本面」时写
- **两个真相源必须同步（2026-10-16 修复）**：PLC 的 D2500–D3500 是运行时真相，
  `recipes.json` 的机种快照是持久化真相，**示教页重新进入时按快照装载**。
  因此「下发点表」与「坐标示教」写完 PLC 后会把<b>本表各列覆盖到的字</b>并入当前机种快照
  （不整段回读——机种区段里还有参数等本地未下发的数据，整段回读会把它们盖回旧值）。
  机种页「保存机种」仍是"以 PLC 整段为准"的显式回读。
- **面启用开关**：默认不启用，只有启用的面才写入（防止空点把轴驱动到原点）
- **CSV 交换**：一个机种一个文件（三段式），供 Excel 编辑与机种间拷贝

| 功能 | 操作员 | 工程师 | 管理员 |

| 系统设置 | ❌ | ❌ | ✅ |

**实现要点**

- 权限用**位标志**（`Permission`）而非角色等级比较，将来可给某角色单独开一项而不影响其他角色

- 账号存 `config/users.json`，**PBKDF2-SHA256 迭代 10 万次**，只存哈希与盐；
  校验用 `CryptographicOperations.FixedTimeEquals` 防时序侧信道
- 默认账号 `operator` / `engineer` / `admin`，初始密码均 `123456`，
  带 `IsDefaultPassword` 标记——登录后界面会提示尽快修改
- **导航过滤在 `主视图模型.构建导航()`**：按权限决定哪些页出现在侧栏；
  页面 ViewModel 仍全部构造（单例），只是不显示，切身份时不丢状态
- 控件级权限：管理员专属按钮用 `Visibility` 绑定 `可编辑*` 标志；
  **服务层再校验一次**（如改元件要 `EditManualWidgets`），不只靠界面隐藏

## 十一、报警配置化（已实施）

**需求**：从 PLC 指定地址读状态，映射成具体报警文本；管理员可改文本与地址。

**报警区（硬约束）**

| 区域 | 容量 | 引用形式 |
|---|---|---|
| **M500 – M600** | 101 个位 | `M500`（本身就是位，不缀位号） |
| **D550 – D554** | 5 字 × 16 位 = 80 位 | `D550.1`（必须指定位号） |

**最多 100 条报警**，每条可单独启用 / 停用。

**工作流程**

```
报警扫描服务（周期 500ms）
      ↓ 按软元件区与地址连续性合并读取计划
      ↓ M 区用 FC01 读线圈 / D 区用 FC03 读保持寄存器
      ↓ 位为 1 → 报警服务接口.触发(代码值, 消息, 等级)
      ↓ 位恢复 0 → 报警服务接口.清空(代码值) → 自动消除并进历史
```

**配置**：`config/alarms.json`

```json
{
  "alarms": [
    { "id": "A001", "level": "Critical", "message": "设备急停被按下",
      "suggestion": "确认现场安全后复位设备",
      "address": "M500", "bit": -1, "enabled": true },
    { "id": "A005", "level": "Warning", "message": "压装压力偏低",
      "address": "D550", "bit": 0, "enabled": false }
  ]
}
```

**校验规则**（`报警定义服务.校验`）

- 地址必须落在 M500–M600 或 D550–D554
- D 区**必须指定位号**，否则一个 16 位的字只能放一条报警
- 位号 0–15 或 -1
- 条数上限 100；编号不可重复

**编辑入口**：「报警记录」页底部的「报警配置」区（仅管理员可见），
可新增 / 编辑 / 删除 / 启停，改完写回 `alarms.json`。

## 十二、手动页元件配置化（已实施）

**配置**：`config/manual-widgets.json`

```json
{
  "widgets": [
    { "id": "cyl-1", "type": "Cylinder", "name": "上料气缸", "order": 1, "address": "M220" }
  ]
}
```

**元件类型**

| 类型 | 地址字段 | 行为 |
|---|---|---|
| **气缸** | `address`（单个） | **单线圈：置位 = 伸出，复位 = 缩回** |
| 按钮 | `address` | 按下时发一个短脉冲 |
| 指示灯 | `stateAddress` | 只读显示 ON / OFF |

> **气缸是单线圈，不是双线圈。** 一个地址搞定伸出与缩回，
> 不要拆成"伸出位 + 缩回位"两个地址——现场用的是单电控阀。

**地址硬约束：只允许 M 区。**

上位机只置位内部继电器，由 PLC 程序决定何时驱动 Y 输出——
这样上位机**不会绕过 PLC 的联锁逻辑**直接动作执行机构。

这条约束在**服务层**兜底：`手动控件服务.解析设备中继()` 解析地址后
检查软元件类型，非 M 区直接抛异常，即使配置文件被手工改错也不会执行。

**X / Y 点只用于 IO 监控**（只读），既不作为控制输出，也不作为报警源。

## 十七、关键工程约定（踩过的坑）

> 这一节是从实际故障中总结的，不是理论清单。**新增代码必须遵守。**

### 17.1 开发环境

1. **执行任何 dotnet 命令前必须** `source ~/.workbuddy/dotnet-env.sh`
   沙箱剥离了 Windows 环境变量（APPDATA/ProgramData/ComSpec），否则 NuGet 报
   `Value cannot be null. (Parameter 'path1')`。

2. **`rm -rf` 的路径里绝对不允许出现 `..`**
   2026-09-10 执行 `rm -rf "$OUT" "$OUT/.."` 时 `$OUT/..` 解析成 `docs/` 本身，
   把整个文档目录删掉且无备份。清目录只写绝对路径，删除前先 `ls` 确认。

### 17.2 通信与数据

3. **X 点默认读离散输入区（FC02），Y 点默认读线圈区（FC01）**——输入走输入表、输出走输出表，
   与 Modbus 语义一致（2026-10-17 修正，此前 X 误配在线圈区，现场"Y 对、X 错"）。
   机型把 X 放在线圈表时，在 `io-points.json` 元的 **`X区域`/`Y区域`** 显式指定
   （出厂配置已显式写成 `"X区域": "离散输入"` / `"Y区域": "线圈"`），保存后重启生效。
   自动回退只信任两种证据：当前位区**读取抛异常**（无应答），或当前位区**从未读到过信号**
   而另一位区有信号。"读到过信号"即证明位区是活的——之后的全 0 是物理点全部断开，
   绝不能据此切到备用位区（机器空闲时备用区的无关位会把整块永久带错）。
   拿不准物理 IO 在哪个功能码上时，用 IO 页的「**IO 通信诊断**」：它把 X / Y 段在
   FC01 / FC02 上的原始位并排读出来，结论直接告诉现场该把 `X区域`/`Y区域` 配成什么。

4. **PLC 状态字约定 `0=空闲中 1=运行中 2=待机中 3=复位中 4=报警中`**（2026-10-16 现场确认，默认寄存器 D6，
   运行监控页可由管理员改地址），与 C# `DeviceState` 枚举（`未知=0` 哨兵）语义不同，
   一律经 `设备服务.映射状态字()` 映射，**禁止直接强转**；界面显示文案见
   `运行视图模型.应用状态`（图标 + 文字双编码，颜色只做辅助）。

5. **坐标是 float32，一致性校验必须用容差（0.005），禁止 `==`**
   `9999.99` 实际存为 `9999.99023`、`−999.99` 存为 `−999.98999`；显示一律 `F2` 格式化。

6. **常闭（NC）输入点在 `io-points.json` 标 `inverted: true`**；模拟器写原始位时注意
   "未动作 = 触点闭合 = 1"。

### 17.3 架构

7. **只订阅事件流的服务必须同时在构造函数里拉一次快照**
   事件只推送变化，构造晚于首轮采集会漏掉初始状态（`设备服务` 踩过）。

8. **多个服务写同一个文件时，必须共享一份内存副本**
   `RecipeService` 与 `TeachService` 都写 `recipes.json`，曾因各持副本而互相覆盖，
   最终抽出 `配方存储` 单例解决。

### 17.4 自检手段

9. **XAML 的 `{StaticResource}` 在加载时求值，键名写错编译期不报错**

   2026-09-10 踩过：三个新对话框引用了主题里不存在的 `AppFontFamily` /
   `PageBackgroundBrush` / `WarningDarkBrush`。表现为**程序能启动、8 页自检全过，
   一点「切换身份」就崩**——因为 `--smoke` 只遍历导航页，对话框不在导航里。

   **约定**：资源键一律用 `Themes/*.xaml` 已定义的（字体 `UiFontFamily`、
   页面底色 `SurfaceAltBrush`、警告色 `WarningBrush`）。

   **防护**：`--smoke` 现已覆盖全部对话框——实例化但不显示，引用不存在的资源
   会让退出码非 0。新增对话框时记得加进 `应用.验证对话框()`。
