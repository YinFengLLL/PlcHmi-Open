# 可配置弹窗（M 区实时弹窗）

**日期：** 2026-10-13 ／ **版本：** v1.1「点胶锁付机」／ **文档号：** 15

> 现场口径（2026-10-13）：**弹窗显示与 M 区是实时关系——闭合有效则显示，无效则不显示。**

## 一、是什么

管理员可以在「系统设置 → 弹窗设置」里维护任意个弹窗。每个弹窗由三部分组成：

| 组成 | 说明 |
|---|---|
| **触发地址** | 一个 **M 区线圈**。它闭合（ON）时主界面**居中显示**该弹窗；断开（OFF）**立即消失**。实时关系，不做锁存 |
| **弹窗内容** | 自定义文案（多行） |
| **两个按钮** | 名称自定义，各对应一个 **M 区线圈**；按钮是**复归型**——按住置位、松开复位 |

第二个按钮的**名称留空则该按钮不显示**（单按钮弹窗）。

## 二、怎么用（现场流程）

1. 管理员进「系统设置」→ 最下方「弹窗设置（管理员）」卡 → 点「弹窗设置…」。
2. 「＋ 新增弹窗」→ 填名称、触发地址（如 `M1100`）、内容、两个按钮的名称与地址。
3. 「保存」→ **立即生效**（落盘 `config/popups.json`，无需重启）。
4. 设备运行时，PLC 把 `M1100` 置 ON → 主界面居中弹出该弹窗；PLC 复位 `M1100` → 弹窗消失。
5. 操作员按住某个按钮 → 上位机把对应线圈**置位**；松开 → **复位**。
   典型 PLC 逻辑：按钮线圈上升沿 → 处理业务并**复位触发线圈** → 弹窗自动消失。

## 三、实现要点

| 点 | 做法 | 为什么 |
|---|---|---|
| 触发检测 | `弹窗监控服务` 连接期间每 **600 ms** 轮询各触发线圈（每次 1 个线圈） | 触发地址由管理员随时增删，轮询引擎按 `tags.json` 固定点位工作，动态点位自己读最稳；数量是"个位数"量级，开销可忽略 |
| 显示/消失 | 触发键变化 → `弹窗宿主视图模型.当前弹窗` → 主窗悬浮层 `有弹窗` | 与触发线圈是实时关系：ON 显示、OFF 消失，不做任何锁存 |
| 多弹窗同时触发 | 取**第一个命中**的弹窗 | 一屏只该有一个弹窗；避免叠成一摞无法操作 |
| 按钮交互 | 复用「点动手势」（按住 → 置位，松开 → 复位） | 与手动调试页的点动同一套"按住才动、松开即停"手感，操作员不用重新学 |
| 地址约束 | 触发地址与两个按钮地址**必须是 M 区**，且按钮地址不得与触发地址相同 | M 区是全工程一致的边界（上位机只驱动内部继电器，Y 输出由 PLC 程序决定）；同址会让按住按钮期间反复触发 |
| 轮询启动 | 循环随服务（单例）**常驻**，每一轮自己判断连接状态：未连接跳过、连上即读 | **曾经的真实缺陷**：原写法是"等连接状态变为已连接的事件再启动循环"，而服务（主窗 ViewModel 构造时）第一次被创建时 PLC 往往**已经连上**，此后不再有该事件 —— 循环永不启动，现场表现就是"M 都闭合了但界面毫无反应"。改为常驻循环后与事件次序无关 |
| 断线行为 | 断开期间各轮直接跳过、不报错；重连后自动继续 | 通信抖动不该让进程里攒一堆僵尸循环，也不该让弹窗功能永久失效 |
| 轮询异常 | **循环内**逐轮 try/catch：单轮失败只记警告，下轮继续 | 写在循环外时，一次通信异常会永久终止轮询（日志里只有一条 Warning，现场极难定位） |

## 四、配置文件

`config/popups.json`（出厂模板：`发布包/出厂配置/popups.json`）：

```json
{
  "弹窗集合": [
    {
      "键": "demo1",
      "名称": "换料提醒",
      "触发地址": "M1100",
      "内容": "料盘已用完，请更换料盘后确认继续。",
      "按钮一名称": "确认更换",
      "按钮一地址": "M1120",
      "按钮二名称": "稍后处理",
      "按钮二地址": "M1121"
    }
  ]
}
```

- 保存走**原子写 + `.bak`**，与其它配置一致；保存后服务自动重读，立即生效。
- `键` 由程序生成，用于标识同一弹窗；手工编辑时保持唯一即可。
- 文件不存在时弹窗功能**静默待命**（不报错、不拦启动）。

## 五、弹窗不出现时怎么查（看日志三行）

| 日志 | 含义 |
|---|---|
| `已装载 N 个可配置弹窗` | 配置读到了。若这里是 `未配置弹窗（…popups.json 不存在）` → 该机还没有弹窗配置（本版首次启动会自动补齐出厂模板） |
| `弹窗「X」监听触发地址 M1100（线圈 1100）` | **地址解析成功**，监听已建立。若这里是 `触发地址「…」不是有效的 M 区线圈` → 地址写错（非 M 区 / 格式不对），该弹窗被跳过 |
| `弹窗「X」触发（M1100 闭合），主界面已显示` | 上位机确实读到了线圈闭合并显示了弹窗；若界面仍无弹窗，问题在界面层而不是通信层 |

断开会记 `弹窗触发线圈已断开，弹窗收起`。

## 六、已知边界

- 弹窗**不做锁存**：PLC 必须保持触发线圈为 ON，弹窗才持续显示——这正是"实时关系"的定义。
- 弹窗按钮**不带上位机侧业务动作**，只把线圈置位/复位；要不要报警、要不要停机，由 PLC 程序决定。
- 触发地址写错（非 M 区、地址非法）时：编辑器保存前就能拦下并给出原因；
  手工改坏 JSON 的情形只在**轮询时**记警告并跳过该弹窗（不影响其它弹窗与整机）。
