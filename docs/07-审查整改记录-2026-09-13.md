## 二、🔴 红线级问题（已修）

### 1. `recipes.json` 有一条完整的数据丢失链（R3）

**三环相扣，缺一环都不致命，合起来不可恢复：**

1. `AtomicFile` 只 `Dispose` 不落盘 —— 断电时"改名已生效、数据还在写缓存"，
   文件可能停在 0 字节。`File.Replace` 保证的是**原子性**，不是**持久性**。
2. `.bak` **只写不读**：全仓库 grep 确认只有 `AtomicFile` 写它，没有任何加载器读它。
   注释里写的"供回滚"是句空话。
3. `RecipeStore.Load()` 解析失败只记日志、以空数据启动；**下一次保存**会把这份坏内容
   通过 `File.Replace` 轮换成 `.bak`，**覆盖掉唯一的好副本**。

**修法**：`WriteThroughAsync` 补 `FlushFileBuffers`（`Flush(true)` 无异步版本，
丢线程池执行以规避 CA1849）；新增 `ConfigFileLoader` 统一处理"主文件坏 → 读 `.bak`
→ 修复主文件"；主文件为 0 字节时不再轮换成 `.bak`。

**验证**：新增 `ConfigFileLoaderTests`（9 例）+ `RecipeStoreRecoveryTests`（2 例）。
并实测：把 `io-points.json` 截断成 23 字节（`.bak` 3932 字节），启动后主文件
自动修复为 3932 字节，程序正常运行。

### 2. 配置损坏 → 静默降级（R3，安全级）

`AlarmDefinitionService` 加载失败时只 `LogError`，`_definitions` 保持空。
**后果：界面一切正常、显示"当前无报警"，而 PLC 每一个故障位都被无视。**
崩溃看得见，失去报警看不见 —— 这是最危险的一种失效。

同一模式还有 6 处：配方、点位表、IO 点位表、参数表、手动页元件、账号。

**修法**：新增 `IConfigHealth` + `ConfigHealthService`，各加载器登记加载结果；
主窗口新增**常驻降级横幅**（不可关闭、不自动消失），启动期配置回退默认值同样登记。

### 3. 服务层零权限校验（R5 明文红线）

规则原文：*"管理员专有功能（延时表 / 按钮表 / 报警 / 元件编辑）双重校验 → 缺失 = 🔴"*

实测：**全部 7 处 `Permission` 检查都在 ViewModel，`PlcHmi.Business` 一处都没有**，
而 `docs/01` §十 却写着"服务层再校验一次"。文档与代码不一致，会误导后续审查者。

**修法**：新增 `IPermissionGuard` + `UserPermissionGuard`，在服务层兜住：
延时/按钮表、报警定义、手动页元件、轴地址、PLC 连接参数（管理员）；
示教写入、切机种、参数下发（工程师及以上）。
校验发生在**参数校验之前、任何状态变更之前** —— 被拒的调用不留痕迹。

**验证**：新增 `PermissionGuardTests`（11 例，含"拒绝后状态未变"）。
测试侧显式声明以受信任身份运行，权限边界由该组单独覆盖。

## 四、💭 刻意没做的事（附理由）

| 项 | 为什么不做 |
|---|---|
| **拆 11 个超 400 行文件** | 标准自己写了"能跑就别乱动"。改为 `tools/check_thresholds.py` 棘轮门禁：基线只允许调小，新文件超标即失败。**重构不应与整改混在一个 PR 里。** |
| **触屏软键盘** | 目标屏已确认为 1920×1080 电脑屏（有键鼠），优先级下降。若将来上触控面板，42 个文本输入控件需要配套数字小键盘（见下"遗留"）。 |
| **ManualView / TeachView 不开触摸平移** | 这两页含"按住才动、松开即停"的点动按钮。开平移后 ScrollViewer 会在手指拖动时抢走触摸，按钮收不到 `MouseUp` —— **正是 `JogGesture` 注释里写的那个事故（"轴会一直动下去"）**。`JogGesture` 目前只处理鼠标事件。正确顺序是**先补触摸事件与 `ManipulationStarting` 拦截，再开平移**。 |
| **删 Windows 错误消息的卫星资源目录** | 收益小（几 MB）、有风险（异常文案变英文）。 |
| **自动重启进程** | 重启循环在现场比崩溃更难查。改为"多次异常 → 明确提示人工重启"。 |

## 六、本次新增的门禁与工具

| 工具 | 作用 |
|---|---|
| `tools/verify.ps1` | Windows 原生一键门禁（纯 Windows 项目不该为了跑门禁先装 Git Bash） |
| `tools/check_thresholds.py` | 代码规模棘轮（单文件 400 行 / `catch(Exception)` 总数） |
| `tools/publish.ps1` | 固化发布流程：清理 + 核对 config/ + 对产物跑 `--smoke` |
| `.github/workflows/verify.yml` | CI 模板（`docs/04` §6 P2 ⑧） |

> ⚠️ **.ps1 文件必须带 UTF-8 BOM。** Windows PowerShell 5.1 会把无 BOM 的 UTF-8
> 当 ANSI 读，中文注释与字符串会乱码并导致**语法错误**（实测：`publish.ps1` 报
> "字符串缺少终止符"）。用编辑器保存时请确认编码为"UTF-8 带 BOM"。

> ⚠️ **行数口径**：`check_thresholds.py` 按**总行数**（含空行）统计，
> 与 `wc -l` / 编辑器一致。早期文档用 PowerShell `Measure-Object -Line`，**不数空行**，
> 数字偏小（`App.xaml.cs` 记 504，实际 722）。以脚本输出为准。
