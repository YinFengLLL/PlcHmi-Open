## 一、诊断结论

对现有 UI 层（`Themes/` 2 个字典 + `MainWindow` + 8 个页面 + 4 个对话框，共 2825 行 XAML）做了四维度实测，结论如下。

### 1.1 诊断总览

| 层面 | 现状 | 评级 |
|---|---|---|
| 设计令牌 | 色彩 52 项齐全；**间距 / 阴影 / 层级 / 动效 4 组缺失** | 待补齐 |
| 组件库 | 现有 8 类样式，**状态与表单组件缺口约 18 类** | 偏薄 |
| 页面布局 | 8 个页面结构统一（`Margin="20"` + 标题块 + RowDefinitions） | 良好 |
| 无障碍 | **对比度 15/19 达标；键盘焦点态 0 处；图标库未接入** | 需修复 |

### 1.2 做得好的地方（应保留）

1. **色彩架构规范**：`Color` + `SolidColorBrush` 双层定义，语义命名（`Primary` / `Success` / `Danger` / `Warning` / `Muted` / `Off`），并配了 `*Soft` 浅底变体。这套结构可以直接扩展，不需要推倒重来。
2. **配色纪律极佳**：全站硬编码十六进制色值仅 **9 处**，且集中在顶栏的半透明白（`#1AFFFFFF` ~ `#CCFFFFFF`，用于深蓝底上的分隔线与按钮描边）。这在同类项目里属于优秀水平。
3. **页面骨架一致**：8 个页面都是"外层 `Grid Margin="20"` → `Auto/Auto/*` 行定义 → 页标题块 → 内容区"，没有出现每页各写一套的情况。这意味着后续可以做统一的页面容器，改动面可控。
4. **触摸目标有意识**：已定义 `TouchButtonHeight = 62`、`NormalButtonHeight = 44`，说明设计时就考虑过现场触摸屏操作。

### 1.3 需要修复的问题

按严重度分级。**工控场景下，涉及"现场看不清 / 误操作"的一律按最高级处理。**

#### 🔴 P0-1 颜色对比度：4 组未达 WCAG AA（实测数据）

用 `tools/check_contrast.py` 对 `Palette.xaml` 做了全量计算，结果：

| 组合 | 用途 | 实测 | 门槛 | 结论 |
|---|---|---|---|---|
| 白字 / 成功绿 `#1B8A4B` | **启动按钮** | 4.39:1 | 4.5 | ✗ 差 0.11 |
| 白字 / 警告橙 `#E8890C` | **停止按钮** | 2.62:1 | 4.5 | ✗ **差 1.88** |
| 警告橙 `#E8890C` / 白底 | 报警文字、状态灯 | 2.62:1 | 3.0 | ✗ |
| 边框 `#C9D6E5` / 白底 | 输入框边界 | 1.48:1 | 3.0 | ✗ |

**为什么这条是 P0**：`RunView.xaml:75-78` 的"停止"按钮是 `Background="{StaticResource WarningBrush}"` 配默认白字。橙底白字 2.62:1，在车间强光下、或操作员戴护目镜时，**按钮文字基本糊成一片**。而它旁边紧挨着的"急停"按钮是红底白字（5.62:1，达标）——也就是说，**没有视觉障碍的操作员会看错按钮**。

同时 `#E8890C` 作为报警文字色压在白色卡片上也只有 2.62:1，报警条目读起来吃力，这在"报什么警"比"有没有警"更重要的场景里是实质性的可用性缺陷。

**修正方案**（保持色相不变，只降明度，已用脚本求解并验证）：

| Token | 现值 | 建议值 | 用途分工 |
|---|---|---|---|
| `SuccessColor` | `#1B8A4B` (4.39:1) | `#15803D` (5.02:1) | 启动按钮实心底 / 正常状态 |
| `WarningColor` | `#E8890C` (2.62:1) | `#D87F0B` (3.02:1) | **指示灯、图形、边框**（压白底需 3:1） |
| `WarningStrongColor`（新增） | — | `#AC6609` (4.51:1) | **实心按钮底、正文文字**（需 4.5:1） |
| `BorderStrongColor` | `#C9D6E5` (1.48:1) | `#8C96A0` (3.01:1) | 交互控件边界（输入框、按钮描边） |

> **注**：`BorderColor #E1E8F0` 保持不变——它只做卡片分组，不承担信息传递，靠背景色差和间距已足够区分。只有**交互控件的边界**才需要满足 3:1（WCAG 1.4.11）。

> **橙色拆成两个 token 的理由**：一个颜色没法同时满足"亮到像警示灯"和"暗到白字看得清"。拆开后，指示灯用亮橙（视觉冲击力），按钮和文字用深琥珀（可读性），两者是同一色相系，观感统一。

#### 🔴 P0-2 键盘焦点态完全缺失

全站 `FocusVisual` / `IsKeyboardFocused` / `KeyboardNavigation` / `AutomationProperties` 出现次数：**0**。

`Controls.xaml` 里 `ActionButton` 的交互态是这么写的：

```xml
<Trigger Property="IsMouseOver" Value="True">
    <Setter TargetName="Root" Property="Opacity" Value="0.88" />
</Trigger>
```

两个问题：
1. **没有 `IsKeyboardFocused` 触发器** → 用 Tab 键导航时，操作员**看不到焦点在哪**。工程师在现场调试、或触摸屏键盘失效时，只能盲按。
2. **用 `Opacity` 表达 hover 态** → 深蓝底降到 0.88 后，与白字的对比度从 10.04:1 掉到约 8.8:1（仍在安全区），但**如果后续有浅色按钮，Opacity 变淡会让对比度跌破门槛**。正确做法是切换成预设的父级/子级色，而不是整体透明。

#### 🟡 P1-1 间距系统缺失：200 余处魔法数字

统计各页面的 `Margin` / `Padding` 字面值出现频次：

| 值 | 出现次数 | 值 | 出现次数 |
|---|---|---|---|
| `0,0,10,0` | 28 | `0,0,0,14` | 16 |
| `0,7` | 24 | `14,10` | 13 |
| `0,0,0,6` | 20 | `0,0,0,16` | 9 |
| `0,0,0,12` | 20 | `20` | 8 |
| `0,4,0,0` | 17 | `0,0,12,0` | 7 |
| `0,0,8,0` | 16 | … | … |

问题不是"数值不好看"，而是**同一层级的间距在不同页面不一致**：
- `RunView` 卡片间距 = 10px
- `ParamView` 块间距 = 16px
- `IoView` 双栏间距 = 7px
- `ManualView` 用 14px

三者都是"同级卡片之间的距离"，却给了三个不同的值。**视觉节奏因此轻微紊乱**——单页看不出来，来回切页面时会有说不清的"哪儿不对劲"。

更麻烦的是 `0,7` 出现 24 次、`0,11` 出现 5 次。奇数间距通常是为了对齐某个视觉中心而临时凑的，属于典型的"补丁式布局"。

#### 🟡 P1-3 图标库已备好但未接入

`图片库/` 提供了 **40 张手绘矢量图标** + 已生成的 `PlcHmi.Icons.xaml`（52 个 Geometry 资源键，含 `IconPath` / `IconPathLarge` 两个预设样式），配色已对齐 `Palette.xaml`。

但代码库里：**`Images/` 目录不存在，`PlcHmi.Icons.xaml` 未被任何文件引用，`Icon.Nav.*` 出现 0 次。**

当前导航用的是 `Segoe MDL2 Assets` 字体图标：

```xml
<!-- Controls.xaml:160 -->
<Style x:Key="NavItemGlyph" TargetType="TextBlock">
    <Setter Property="FontFamily" Value="Segoe MDL2 Assets" />
    ...
```

三个风险：
1. **字体依赖**：`Segoe MDL2 Assets` 是 Windows 10+ 自带，但**精简版 Windows Server / 工控机定制系统上可能被裁掉**。一旦缺失，全站导航图标变成一排方块（口口口）。工控现场重装系统是常事。
2. **中英混排字重不一致**：字体图标的笔画粗细由字体本身决定，无法微调；而矢量图标的 1.75px 圆头描边是统一设计过的。
3. **顶栏 Logo 也是字体图标**（`MainWindow.xaml:53`，`&#xE7F4;`），同样风险。

#### 💭 P2 打磨项

| 项 | 说明 |
|---|---|
| 无动效 | 全站 `Storyboard` / `VisualState` 出现 **0** 次。图标库 README 里提到的"运行灯呼吸、报警灯闪烁"没做。**报警闪烁在工业 HMI 上是必要的注意力引导手段**，不是装饰。 |
| 首页核心区是占位 | `RunView.xaml:88-98` 的"设备工位状态区"目前是一行占位文字"此处后续放置工位示意与轴位置指示"，占了页面最大的一块面积。这正是 `device` 类 10 张图标（电机/气缸/传送带/机械手…）的用武之地。 |
| 触摸目标偏小 | `NavItem` 内边距 `12,11` → 实际行高约 44px；`InputBox` 高度 34px。若目标机是触摸屏，建议导航项提升到 48px、输入框到 40px。 |
| 顶栏 9 处硬编码白 | 应 token 化为 `OnPrimaryDividerBrush` / `OnPrimarySubtleBrush` / `OnPrimaryGhostBrush` 三档。 |
| 卡片无层级 | 所有卡片都是 1px 边框，报警条、数据卡、占位卡视觉权重相同，缺少"哪个更重要"的暗示。 |

### 2.2 间距系统（4px 栅格）★全新

统一到 4 的倍数。命名直接取像素值，避免"到底是 Space3 还是 12px"的二次查表。

```xml
<sys:Double x:Key="Space4">4</sys:Double>      <!-- 图标与文字、徽标内边距 -->
<sys:Double x:Key="Space8">8</sys:Double>      <!-- 控件内边距、紧邻元素 -->
<sys:Double x:Key="Space12">12</sys:Double>    <!-- 卡片内元素间距 -->
<sys:Double x:Key="Space16">16</sys:Double>    <!-- 卡片内边距 -->
<sys:Double x:Key="Space20">20</sys:Double>    <!-- 页面外边距 -->
<sys:Double x:Key="Space24">24</sys:Double>    <!-- 区块间距 -->
<sys:Double x:Key="Space32">32</sys:Double>    <!-- 大区块分隔 -->
<sys:Double x:Key="Space40">40</sys:Double>    <!-- 页面顶部留白 -->
```

配套 `Thickness` 组合（WPF 里 `Margin` 是四值，直接给组合更省事）：

```xml
<Thickness x:Key="GapRight8">0,0,8,0</Thickness>
<Thickness x:Key="GapRight12">0,0,12,0</Thickness>
<Thickness x:Key="GapRight16">0,0,16,0</Thickness>
<Thickness x:Key="GapBottom4">0,0,0,4</Thickness>
<Thickness x:Key="GapBottom8">0,0,0,8</Thickness>
<Thickness x:Key="GapBottom12">0,0,0,12</Thickness>
<Thickness x:Key="GapBottom16">0,0,0,16</Thickness>
<Thickness x:Key="GapBottom24">0,0,0,24</Thickness>
<Thickness x:Key="CardPadding">16,14</Thickness>
<Thickness x:Key="PageMargin">20</Thickness>
```

**迁移规则**（把现有魔法数字映射过去）：

| 现值 | 去向 | 说明 |
|---|---|---|
| 3, 4, 5 | `Space4` | |
| 6, 7, 8 | `Space8` | |
| 10, 11, 12 | `Space12` | |
| 14, 16 | `Space16` | |
| 18, 20 | `Space20` | |
| 26 | `Space24` | |

> 映射会带来**轻微视觉位移**（例如卡片间距 10 → 12）。这是必要的代价：换来的是全站节奏一致。建议在同一个提交里全量替换，而不是逐页迁移——逐页迁移会让"新旧间距混用"的过渡期比统一后的差异更难看。

### 2.3 阴影与层级（Elevation）★全新

> **⚠️ WPF 性能红线**：`DropShadowEffect` 在 WPF 里是**软件渲染为主**的高开销效果。一个页面挂 20 个带阴影的卡片，在低端工控机上滚动会明显掉帧。
>
> **因此本方案明确：卡片一律不用阴影，继续用 1px 边框。** 阴影只给真正需要"浮在内容之上"的层。

```xml
<!-- 仅三档，且只用于弹出层 -->
<DropShadowEffect x:Key="Elevation1" BlurRadius="6"  ShadowDepth="1" Opacity="0.06" Color="#0B1F3A" Direction="270"/>
<DropShadowEffect x:Key="Elevation2" BlurRadius="12" ShadowDepth="2" Opacity="0.10" Color="#0B1F3A" Direction="270"/>
<DropShadowEffect x:Key="Elevation3" BlurRadius="24" ShadowDepth="6" Opacity="0.16" Color="#0B1F3A" Direction="270"/>
```

| 层级 | 用途 | 实现方式 |
|---|---|---|
| Base | 页面背景 | `BackgroundBrush` |
| Raised | 卡片、面板 | `SurfaceBrush` + 1px `BorderBrush`（**无阴影**） |
| Overlay | 下拉菜单、ToolTip | `Elevation2` |
| Modal | 对话框 + 遮罩 | `Elevation3` + `#66000000` 遮罩 |

**交互反馈用"边框变色"替代"阴影浮动"**：鼠标悬浮时 `BorderBrush` 从 `#E1E8F0` → `#8C96A0`，比加阴影既省性能又更符合工业界面的克制气质。

### 2.4 字体系统

现有字体族选择是对的（`Microsoft YaHei UI` 正文 + `Consolas` 数字），**保留**。补齐字号梯度：

| Token | 值 | 用途 |
|---|---|---|
| `FontSizeDisplay` ★新增 | 32 | 首页核心指标（节拍、产量），需更远端可读 |
| `FontSizeMetric` | 26 | 一般指标卡 |
| `FontSizeTitle` | 20 | 页面标题 |
| `FontSizeHeading` | 15 | 区块标题 |
| `FontSizeBody` | 13 | 正文 |
| `FontSizeCaption` | 12 | 辅助说明 |
| `FontSizeMini` ★新增 | 11 | 状态灯数值（现 `IoView` 硬编码 11） |

**数字排版**：所有数值必须用 `NumericFontFamily` + `TextAlignment="Right"`（现有 `NumericInputBox` 已做，需推广到表格与指标卡）。等宽数字让"跳动"的坐标值不会左右晃，这在监控轴位置时非常重要。

### 2.5 无障碍标准（WCAG 2.1 AA）

| 要求 | 具体标准 | 落地方式 |
|---|---|---|
| 对比度 | 正文 4.5:1，大号/图形 3:1 | `tools/check_contrast.py` 进 CI，回归即失败 |
| 键盘可达 | 所有交互元素可 Tab 到达并有可见焦点 | 全局 `FocusVisualStyle` + `IsKeyboardFocused` 触发器 |
| 焦点顺序 | 与视觉顺序一致 | 依赖 XAML 声明顺序，避免 `TabIndex` 乱序 |
| 状态不靠色 | 颜色 + 图标/文字双重编码 | 状态灯旁必带文字；报警带图标；表格用图形标记 |
| 触摸目标 | ≥ 44×44px | `TouchButtonHeight=62` ✅；`NavItem` 44 → 建议 48 |
| 减少动效 | 尊重系统"减少动态效果"设置 | 报警闪烁用 `SystemParameters.ClientAreaAnimation` 开关 |
| 错误预防 | 危险操作二次确认 | 急停、清空配方、删除机种加确认对话框 |

**关于报警闪烁与"减少动效"**：闪烁是工业场景的必要功能，但必须做成可关闭的。建议在 `SettingsView` 加一个"报警闪烁提示"开关，默认开启，并读取系统辅助功能设置。

## 三、组件库蓝图

将 `Controls.xaml`（214 行）拆为四个字典，按职责分层：

```
Themes/
├─ Palette.xaml          色彩 · 间距 · 阴影 · 字体 · 尺寸（令牌层，零样式）
├─ Controls/
│  ├─ Buttons.xaml       按钮族
│  ├─ Forms.xaml         表单族
│  ├─ DataDisplay.xaml   数据展示族
│  ├─ Feedback.xaml      反馈族
│  └─ Navigation.xaml    导航族
└─ Icons.xaml            ← 由 图片库/xaml/PlcHmi.Icons.xaml 拷入
```

### 3.1 按钮族（Buttons.xaml）

```xml
<!-- 尺寸三档 -->
ButtonSm    高 34   字号 12  内边距 14,0
ButtonMd    高 44   字号 14  内边距 18,0
ButtonLg    高 62   字号 17  内边距 24,0   ← 触摸 / 首页主操作

<!-- 语义五色（全部基于令牌，禁止页面内手写颜色）-->
ButtonPrimary    PrimaryBrush       白字
ButtonSuccess    SuccessBrush       白字   启动
ButtonWarning    WarningStrongBrush 白字   停止
ButtonDanger     DangerBrush        白字   急停
ButtonNeutral    SurfaceBrush + BorderStrongBrush   主蓝字   复位 / 取消

<!-- 全部按钮统一具备 -->
Default → Hover(背景加深一档) → Pressed(再深一档) → Focus(2px 焦点环) → Disabled(OffBrush + TextDisabledBrush)
```

**关键修正**：`RunView` 里那 4 个大按钮目前是 `Style="{StaticResource ActionButton}"` + 各自手写 `Background`。改为直接用 `ButtonSuccess` / `ButtonWarning` / `ButtonNeutral` / `ButtonDanger` 四个语义样式——**颜色由设计系统决定，页面不再有权指定**。这样以后再调色，只改一个地方。

### 3.2 表单族（Forms.xaml）

`TextBox`（默认/数值/密码/搜索）、`ComboBox`、`CheckBox`、`RadioButton`、`ToggleSwitch`、`Slider`、`DatePicker`

统一规格：高度 40（触摸场景；桌面场景 34）、圆角 `ControlCornerRadius`、边框 `BorderStrongBrush`、焦点态 2px `FocusRingColor` 环 + 光晕。

### 3.3 数据展示族（DataDisplay.xaml）

`DataTable`（表头 + 斑马纹 + 固定列宽 + 行悬浮）、`ListRow`、`Badge`（计数/状态徽标）、`StatusDot`、`ProgressBar`、`EmptyState`、`SkeletonRow`

`Badge` 是当前最缺的：报警页需要"未确认 3"这样的计数提示，现在只能用纯文字表达。

### 3.4 反馈族（Feedback.xaml）

`ToolTip`（替换系统黄底黑字）、`DialogHost`（遮罩 + 居中卡片 + Elevation3）、`Toast`、`AlarmBanner`（分级：正常/预警/报警/故障，四色 + 图标）、`InlineValidation`

### 3.5 导航族（Navigation.xaml）

`NavItem`（升级为矢量图标版）、`NavItemIcon`、`TopBar`、`Breadcrumb`、`TabStrip`

**导航项升级设计**：

```xml
<Style x:Key="NavItemIcon" TargetType="Path">
    <Setter Property="Style" Value="{StaticResource IconPath}" />
    <Setter Property="Stroke" Value="{Binding RelativeSource={RelativeSource AncestorType=ListBoxItem}, Path=Foreground}" />
</Style>
```

配合现有 `NavItemText` 的 `DataTrigger`（选中变白），图标会跟随文字自动变色——**这正是图标库设计时预留的 `currentColor` 能力**。

## 七、待确认的决策点

以下几点需要需求方拍板，我按推荐方案标注了倾向性：

1. **橙色拆分策略**
   - 方案 A（推荐）：拆成 `WarningColor #D87F0B`（指示灯/图形）+ `WarningStrongColor #AC6609`（按钮/文字）。观感更亮，语义更准。
   - 方案 B：只保留一个 `#AC6609`。token 更少，但指示灯会显得发闷、不够"警示"。

2. **间距统一的范围**
   - 方案 A（推荐）：全量替换为 4px 栅格，接受一次性的轻微位移。
   - 方案 B：只统一"同级元素间距"，保留各页面的局部微调。改动小，但魔法数字不会消失。

3. **卡片阴影**
   - 方案 A（推荐）：卡片不用阴影，只用边框；阴影仅给弹出层。**理由：WPF `DropShadowEffect` 在低端工控机上有掉帧风险。**
   - 方案 B：卡片加极轻阴影（`Elevation1`）。观感更"现代"，但需实机验证性能。

4. **图标替换范围**
   - 方案 A（推荐）：导航 + 顶栏 + 状态灯 + 按钮全部替换。
   - 方案 B：只替换导航（最小改动，但风格不统一）。

5. **触摸屏适配档位**
   - 需要确认目标机是**触摸屏**还是**鼠标键盘**。是触摸屏的话，`NavItem` 44 → 48、输入框 34 → 40、按钮保持 62。

6. **是否规划深色主题**
   - 现有只有浅色。若车间有夜班或暗环境需求，建议在 P1 令牌阶段就把色值做成可切换结构（`Palette.xaml` + `Palette.Dark.xaml`），后期加主题成本极低；否则后续补做需要返工。

7. **实施起点**
   - 建议 P0 立刻做（半天工作量，纯收益零风险），P1-P3 按上表推进。
