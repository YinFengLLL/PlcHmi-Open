## 二、发布包结构

```
点胶锁付机\
├─ 点胶锁付机.exe          程序入口（开源版不带自定义图标）
├─ 点胶锁付机.dll / *.dll  运行时（自包含，免装 .NET）
├─ zh-Hans\                唯一的卫星语言目录（其余语言不出包）
├─ 出厂配置\               出厂配置模板（11 个 JSON）—— 不是 config/
└─ 说明.txt                首次部署 / 覆盖升级须知（唯一一份说明文档）
```

运行时自动生成、不出包：`config\`（首次启动从模板补齐）、`logs\`、`data\`。

## 三、覆盖升级为什么不丢数据

升级动作就是"把新版本目录覆盖到原程序目录"。三种情况：

| 情况 | 结果 |
|---|---|
| 覆盖程序文件（exe/dll） | 正常更新 |
| 覆盖到 `config\` | **不可能**——包里没有 `config\`，只有 `出厂配置\` 模板 |
| 覆盖 `出厂配置\` | 覆盖的只是模板；程序启动时**只补缺失文件**，现场已改的 `recipes.json`（机种与点表）、`appsettings.json`（PLC 连接参数）、`users.json`（账号）等一律保持原样 |

新版本**新增**的配置文件会在下次启动时自动补进 `config\`，日志记一条：

```
已从出厂配置补齐 N 个缺失的配置文件：xxx.json（已有文件一律不覆盖）
```

### 现场可改配置 → 文件对照表（升级全部保留）

| 现场改过的东西 | 存放文件（`config\`） |
|---|---|
| 机种与点表数据（D2500–D3500 快照） | `recipes.json` |
| 全局参数（轴速度等，机种区外） | `parameters.json` |
| PLC 连接参数（IP / 端口 / 协议模式） | `appsettings.json` |
| **报警条目**（新增 / 改文本 / 改地址） | `alarms.json` |
| **IO 点位与名称**（新增栏 / 改名） | `io-points.json` |
| **手动控件**（气缸/按钮/指示灯 + 新增的 D/M 元件地址） | `manual-widgets.json` |
| 运行监控页元件地址 | `tags.json` |
| **参数地址 / 轴地址 / 点表列基址** | `recipe-config.json` |
| 历史记录数据体（触发位 + 各列） | `history-record.json` |
| 汇川变量表 | `variables.json` |
| 其它点（辅助点位）定义 | `aux-points.json` |
| 延时表 / 自定义按钮 | `param-tables.json` |
| 账号与角色 | `users.json` |
| 报警历史 / 产量历史 / 历史记录数据 | `data\`（运行数据目录，包里没有） |

> **新版自带点位怎么进现场？** 覆盖升级只补齐"缺失的文件"，已存在的现场文件不会被覆盖，
> 因此新版在 `tags.json` 里新增的点位（如 v1.3.2 的工位状态三灯与已锁附颗数）在现场是缺的。
> 程序对此有两道处理：① 启动时日志提示 "点位 {Tag} 不在 tags.json 中，运行页元件 {Name} 退回默认地址"；
> ② 管理员在运行页「编辑地址」里改这些元件的地址并保存时，按出厂定义（类型 / 访问 / 分组）
> **自动补建**缺失点位并随整表落盘。因此现场只需"进一次编辑地址 → 确认 → 保存"即可补齐。

> 即：**现场新增的 D 区 / M 区元件、报警条目、IO 名称、控件、参数地址**全部落在
> `config\` 的对应文件里；发布包不含 `config\`，覆盖升级一律保留。
>
> <b>刻意的取舍</b>：文件级"只补缺失"意味着——如果**上位机侧**（开发机）新增了某个
> 报警/元件条目，它不会自动进入一台**已有配置**的机台（那个文件已存在，不会被覆盖）。
> 这类条目请在机台上用界面新增（报警页 / 手动页 / IO 页均支持），或由工程师对照合并
> 对应 JSON。自动覆盖现场文件是丢数据的最常见原因，两害相权取其轻。

> 兜底建议（已写进 `说明.txt`）：升级前把整个 `config\` 拷一份到别处。
> 程序自身也在每次写配置时生成 `.bak`，损坏时启动会自动回退。

## 四、代码与脚本

| 位置 | 职责 |
|---|---|
| `配置路径.出厂模板目录` / `补齐缺失配置()`（Business） | 模板目录定位与"只补齐、不覆盖"的复制逻辑 |
| `启动准备.执行()`（App） | 启动期顺序：建目录 → 补配置 → 可写性预检（顺序不能反，预检要探补齐后的状态） |
| `tools/publish.ps1` | 发布 + 清理（pdb/createdump/语言目录）+ `config/→出厂配置/` + 自检（专门验证"无 config 时从模板补齐"路径）+ 生成 `说明.txt` |

## 四 bis、程序图标与标题栏（2026-11-26 开源版口径）

**开源版不带任何公司标识：不嵌入 Logo 原图、不生成 `app.ico`、顶栏不显示图标。**

| 位置 | 现状 |
|---|---|
| 标题栏左上角 | 只显示站名文字（`工位名称` / `工位副标题`），无图片元素 |
| 窗口 `Icon` / exe 图标 | 均不指定，exe 与任务栏使用系统默认图标 |
| 仓库文件 | 公司 Logo 原图（`图片库/…logo.PNG`）、`src/PlcHmi.App/app.ico`、`tools/make_app_icon.*` 均已从代码与历史提交中移除 |

需要换成自己的图标时：

1. 放一份 `app.ico` 到 `src/PlcHmi.App/`；
2. csproj 加回 `<Resource Include="app.ico" />` 与 `<ApplicationIcon>app.ico</ApplicationIcon>`；
3. 顶栏如需显示图片，在 `MainWindow.xaml` 站名 `StackPanel` 前加一个 `<Image>` 即可。
