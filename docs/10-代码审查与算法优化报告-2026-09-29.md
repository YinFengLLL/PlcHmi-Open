# PlcHmi 全面代码审查与算法优化报告

**日期：** 2026-09-29 ／ **范围：** `src/` 全部五个项目（Core / Communication / Business / App / Tests）+ `config/` + `tools/`
**方法：** 逐文件通读源码（非抽样），所有发现均附文件路径 + 行号证据。
**约束：** 保持原有功能不变；不引入新技术栈；所有建议可落地。

---

## 总体评价

工程素养整体较高：红线（地址字序、UI 线程、原子落盘、权限守卫）在多数路径执行到位；不可变模型（`PLC地址`、`标签新值`）、原子写 + .bak 自恢复、历史记录握手状态机、变量表双字典索引等是良好示范。**主要风险集中在三类：**

1. **防线执行不一致**——同一道防线 A 类做了 B 类漏了（权限守卫、.bak 回退、克隆拷贝、字序拆分）；
2. **3 处确凿的安全/数据缺陷**——脉冲取消不复位（线圈卡 1）、机种号真相分裂（示教点写错机种）、连接失败泄漏 Socket；
3. **热路径低效**——变化检测容差被架空、IO 每周期 O(n²) 查找、历史记录 O(n²) 写放大、UI 大列表无虚拟化。

## 高优先级（建议立即修复，共 12 项）

### H1. 手动控制脉冲取消后不复位，M 线圈卡在置位态【安全】
- **位置：** `src/PlcHmi.Business/Services/ManualControlService.cs:94-96`
- **问题：** `写 true → Task.Delay(脉冲, 取消令牌) → 写 false`，`Task.Delay` 抛 `OperationCanceledException` 时复位写永不执行，气缸/命令卡在动作态。同库 `TagWriter.cs:184-192` 已有正确范本（`try/finally` + `CancellationToken.None` 无条件复位），本处是防线漏执行。
- **改进：** 改为 finally 复位结构，复位写用 `CancellationToken.None`。

### H2. 配方初始化后"当前机种号"两份真相分裂，示教点会写错机种【数据丢失】
- **位置：** `src/PlcHmi.Business/Services/RecipeService.cs:112-122`（`异步初始化` 只设 `_当前号`，从未调 `_存储.设置当前()`）；`TeachService.cs:576` 落盘用 `_存储.当前配方号`
- **场景：** 断电后 PLC 机种号为 5、recipes.json 里为 1 → 内存载入机种 5 点表，示教落盘却写进机种 1 的条目，机种 1 被覆盖、机种 5 丢失。
- **改进：** `异步初始化` 确定 `_当前号` 后立即同步存储层；中期删除一份真相（服务层直接转发存储层）。

### H3. 连接失败路径泄漏 ModbusTcpClient Socket
- **位置：** `src/PlcHmi.Communication/Modbus/FluentModbusTcpClient.cs:61-83`
- **问题：** `Connect` 抛异常时 catch 里的 `释放客户端()` 释放的是 `_客户端` 字段（此时为 null 或旧实例），局部新建的 `客户端` 永不 `Dispose`。断线重连指数退避场景每次失败泄漏一个 Socket——恰是最高频执行的路径。
- **改进：** catch 中直接 `try { 客户端.Dispose(); } catch {}`，成功后才转交所有权。

### H4. 权限红线破口：手动控制 / 设备启停 / 配方导入重命名无服务层校验
- **位置：**
  - `ManualControlService.cs:32-44` —— 整个服务无权限守卫注入，`设置启用`（line 53）、点动、线圈写全部零校验；
  - `DeviceService.cs:28,132-160` —— 启动/停止/重置/清除数据零校验；
  - `RecipeService.cs:331-342, 491-550` —— `异步重命名`、`异步从文件导入CSV` 无 `_权限.要求`（同类 `异步切换`:147 有）。
- **改进：** 三处注入 `权限守卫接口`；按"改结构/删数据=管理员，改值/动作=操作员及以上"补齐。

### H5. 内部可变 List 直接暴露 + 保存无校验：权限被绕过 & 集合并发修改
- **位置：** `AlarmDefinitionService.cs:55`、`ParamTableService.cs:79-89`、`ManualWidgetService.cs:38`（三处同构：`集合 => _内部列表` + `异步保存` 无校验）
- **问题：** ① 调用方可直接 `Add` 后调无校验的 `异步保存()`，绕过有校验的 `添加()`；② `AlarmScanService.cs:144` 后台线程每 500ms 枚举该 List，UI 线程同时增删改 → `InvalidOperationException: Collection was modified`，异常被吞掉记 Warning，表现为"编辑报警定义瞬间一整轮扫描丢失"。
- **改进：** 属性返回快照（`IReadOnlyList` 包 `ToArray()`）+ `异步保存` 加权限校验，两者都做。

### H6. 变化检测 1e-9 容差被原始值精确比较架空，浮点点位每周期刷事件
- **位置：** `src/PlcHmi.Business/Services/TagValueService.cs:65-68`
- **问题：** 四个 OR 条件中 `!Equals(上一个.值, 值.值)` 对 float 原始值做位级精确比较，任何抖动即判变更——第四项缩放后容差判断永远没机会生效。"仅变化时推送"对浮点失效，UI 刷新率退化为轮询频率（100ms），下游属性分配/图表重绘全部被放大。
- **改进：** 原始值为 `double/float` 时改按容差比较，或缩放后值在容差内相等时跳过原始值比较。**优化目标：浮点点位事件量从 10 次/秒/点 降至实际变化次数。**

### H7. 轮询计划把非线圈区位元件硬编码为保持寄存器读取
- **位置：** `src/PlcHmi.Business/Services/PollingEngine.cs:218-229, 276`
- **问题：** 合并只按"位/字"二分，方案区域写死 `保持寄存器`。中型 PLC（AM600/AC800）的 IX 离散输入区 Bool 点会被用 FC03 去读，数据必错；`异步轮询标签` 中 `case 离散输入`（line 428）成死代码。小型 PLC 未暴露是因为其位元件恰好全在线圈区。
- **改进：** 合并按 `区域` 分组，每个区域各自连续合并。

### H8. IO 轮询热路径：每周期重复正则解析 + 每点 O(n) 查找 + 跨度无合并上限
- **位置：** `PollingEngine.cs:370-410`（每 100ms 对全部 IO 点 `尝试解析` + `Min/Max`）；`IoPointService.cs:52,237-239`（`更新状态` 内两次 `FirstOrDefault`）
- **问题：** ① 配置不变时地址解析是纯浪费；② 数百 IO 点 × 每点两次线性搜索 = 每秒数十万次字符串比较；③ 稀疏点（X0 与 X1777）一次读 1024 线圈只取几个点。
- **改进：** 解析结果在 `准备方案列表` 阶段缓存（IO 表变更事件失效）；`IoPointService` 建 `Dictionary<string, IO点位>`（OrdinalIgnoreCase）索引，查找 O(n)→O(1)、每周期 O(n²)→O(n)；IO 块合并复用已有 `合并地址` 并加最大间隔阈值（对照报警扫描的 `最大合并间隔 = 16`）。

### H9. 历史记录每条全量重写当天文件，O(n²) 写放大
- **位置：** `src/PlcHmi.Business/Services/HistoryRecordStore.cs:125-129`
- **问题：** 每追加 1 条序列化整个当日列表重写文件，上限 5000 条/天时当天末尾每条约序列化 5000 条（数 MB JSON + tmp 写 + Replace），全天总量 n(n+1)/2，节拍快时成为磁盘/CPU 热点。
- **改进：** 改增量追加（行式追加 + 启动校验尾行）或内存缓冲 + 每 N 条/T 秒批量落盘。**优化目标：总写入量 O(n²)→O(n)。**

### H10. 历史/报警/IO 三个界面大列表无虚拟化 + 逐条 Add / Insert(0)
- **位置：** `Views/HistoryView.xaml:216`（裸 ItemsControl + ScrollViewer，行内还嵌套 ItemsControl）、`HistoryViewModel.cs:297-323`；`AlarmViewModel.cs:331-348` + `AlarmView.xaml:226,257`；`IoViewModel.cs:349-372`
- **问题：** 非虚拟化 StackPanel 下全量容器实例化；报警风暴或日产数千条时，每次事件 `Clear()` + 逐条 Add（每条一次 CollectionChanged）+ `Insert(0,...)` 使整表失效重排，UI 线程被打满。IO 页每个点状态变化独立 `BeginInvoke` 一次且每次全量重算摘要（O(事件数×点数)/周期）。
- **改进：** 换 `ListBox + VirtualizingStackPanel`（CanContentScroll=True）；批量装载改整体替换/Reset；新记录按倒序维护避免 Insert(0)；IO 摘要加脏标记每周期最多刷一次 + 增量计数。**优化目标：列表刷新从 O(全表重建) 降为 O(可见行)。**

### H11. `历史记录配置.克隆()` 漏拷 `读取后复位触发位`
- **位置：** `src/PlcHmi.Core/Models/HistoryRecordModels.cs:112,127-135`
- **问题：** 界面"克隆→编辑→保存"流程下，管理员曾设为 false 的标志被静默还原为 true，上位机开始复位触发位，与 PLC 程序双写冲突。同类手写 `克隆()` 有 10 余处，是系统性风险。
- **改进：** 补字段；中期纯数据模型改 `record`（编译器生成拷贝），根除手写克隆漏字段。

### H12. 配置冲突：manual-widgets.json 与 tags.json 的 M221/M222 地址踩踏 + 单/双线圈语义矛盾
- **位置：** `config/manual-widgets.json:16-26` vs `config/tags.json:216-241`
- **问题：** M221 在手动页是"压装气缸单线圈"，在点位表是"上料气缸缩回"；手动元件模型是单线圈语义（置位=伸出），tags 是双线圈（伸出/缩回各占一位）。两处配置互相踩踏。
- **改进：** 以 PLC 程序为准裁定单/双线圈方案，统一配置，并把"M 区地址唯一性"纳入启动一致性校验（现有校验框架内扩展，不引新组件）。
