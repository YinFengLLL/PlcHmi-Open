# 机种数据模型：D2500–D3500 快照

**日期：** 2026-10-12 ／ **版本：** v1.1「点胶锁付机」

## 一、现场口径（本次确认）

| 问题 | 结论 |
|---|---|
| 机种保存什么？ | **D2500–D3500（含两端）整段数据**。凡落在这个区间的都是机种区域，跟随机种切换 |
| 区段之外的数据？ | **全局记忆**：凡是 D2500–D3500 以外的 D 区，均不随机种变动 |
| 切换机种要不要下发？ | **要**：写机种号 + 把该机种的 D2500–D3500 写入 PLC，切完即生效（保留手动「下发点表 / 下发机种」按钮） |
| 机种 CSV？ | **同步改造为机种数据 CSV**（保留机种间拷贝 / Excel 编辑能力） |
| 区段外的 D 区 + M 区怎么同步？ | **PLC 是权威**：每次开启软件后轮询读取 PLC 刷新即可（不做"本地为准"的比对） |

## 一 bis、权威方向（两份数据的同步方向相反）

| 数据 | 权威 | 同步方式 |
|---|---|---|
| D2500–D3500（机种区段） | **上位机机种快照** | 「保存机种」读 PLC 存快照；「切换 / 下发机种」写 PLC；切页时按快照装载 |
| D 区其余（轴速度参数、标定、其它点、动作指令…） | **PLC** | 启动时（以及连接建立后补一次）从 PLC 读回**覆盖**内存并落盘留底；进入标定 / 点胶页时再从 PLC 刷新 |
| M 区（手动元件、气缸、按钮等） | **PLC** | 由轮询引擎按 `tags.json` 持续刷新（既有能力） |

启动同步的两个细节（`RecipeService.异步从PLC同步参数`）：

- **单项容错**：某一项越界 / 字数不足 / 通信抖断时只跳过该项并记警告，**不整体拒绝**——
  PLC 里某个残留字不该把整套参数卡住。（对比：操作员按「从 PLC 读取参数」时仍严格整体拒绝）
- **越界不落内存**：PLC 值超出配置范围时保留本地值，避免天文数字进内存被后续下发带到轴上。

> `parameters.json` 的地位也随之变化：它是**离线缓存 / 留底**，不再是"本地为准"的核对基准。
> 启动读不到 PLC 时界面沿用缓存值，一旦连上就按 PLC 刷新。

## 二、改造前 vs 改造后

| | 改造前 | 改造后 |
|---|---|---|
| 机种内容 | 轴速度参数（D1202 等）+ 旧四面示教点 | **D2500–D3500 寄存器快照**（稀疏：只存非 0 字） |
| 参数归属 | 每个机种各一份，**切机种会自动换参数** | 全局一份（`parameters.json`），**切机种不动参数** |
| 点表归属 | 全局文件 `point-tables.json`，不随机种切换 | 属于机种（落在区段内），随机种切换 |
| 机种主存 | `recipes.json` | `recipes.json`（结构变更） |
| 参数主存 | `recipes.json` 内 | `parameters.json`（新增） |
| 点表主存 | `point-tables.json`（已废弃删除） | 机种快照（`recipes.json`） |

> 为什么要改成"整段快照"而不是逐点表建字段：现场口径是"D2500–3500 都是机种区域"。
> 整段快照与这个定义一一对应，以后在区段内新增元件（还是 D2500–3500）**不需要**为每个老机种
> 补字段、也不会出现"老机种数据错位"。

## 三、数据流

```
                ┌────────────────────────── PLC ──────────────────────────┐
                │  D2500–D3500（机种区段，当前机种生效的一份）             │
                │  D1202…（轴参数）、D3600+（标定）、D3700+（其它点）…      │
                └───────▲───────────────────────────┬────────────────────┘
                        │ 下发                       │ 读取
        「下发机种」/「切换机种」/「下发点表」      「保存机种」/「从PLC读取参数」
                        │                            │
   ┌────────────────────┴────────────┐   ┌───────────┴──────────────┐
   │ recipes.json（机种主存）         │   │ parameters.json（全局参数）│
   │  机种号 → D2500–D3500 稀疏快照   │   │  X/Y/Z/ZZ/GlueX/GlueZ     │
   └─────────────────────────────────┘   └──────────────────────────┘
```

**示教页的装载来源**：切页时从**当前机种的快照**解码出点表行（离线可用，看到的是上次保存的数据），
不再读 PLC、也不再读 `point-tables.json`。

## 四、现场操作路径

1. **示教**：锁附/点胶示教页 → 点动到位 → 「保存坐标点」→ 改完按「下发点表」写入 PLC。
2. **保存成机种**：机种管理页 → 「保存机种」→ 把 PLC 当前 D2500–D3500 读回来存成当前机种（落盘 `recipes.json`）。
3. **换机种**：机种管理页 → 目标行「切换」→ 写机种号 + 把该机种快照整段写入 PLC。
4. **全局参数**：参数设置页改轴速度 → 「下发全局参数」；轴速度不随机种变化。
5. **拷贝机种**：机种管理页 → 导出 CSV → 改机种号后导入到目标机种（导入只改本机数据，要生效需再「切换」或「下发机种」）。

## 五、实现要点与约束

- **区段常量**：`机种区段`（Core）——起止 2500/3500、长度 1001、`包含(地址)`。
- **分块读写**：Modbus 单次上限 125 字，区段 1001 字按 100 字一块分 11 次读写（`RecipeService.Snapshot.cs`）。
- **下发前先清零**：快照是稀疏的，若不清零，上一个机种的残留点位会留在 PLC 里（**会真的按老点位动作**）。
- **切换失败不留半截状态**：`异步切换` 先下发快照（机种没数据时在此抛错），成功后才写机种号。
- **机种控制区在区段内**：D3330–D3333（机种号/数量/示教序号/示教面）落在 D2500–D3500 中，
  会被一起保存；切换时末尾以目标机种号覆盖，保证 PLC 里的机种号与上位机一致。
- **CSV 格式**：两段——`[机种]`（号 / 名称）与 `[寄存器]`（`地址,值`，地址写 `D25xx` 形式）；
  导入时区段外地址、非 16 位值一律**整体拒绝**。
- **点表服务不再落盘**：`异步保存本地` 已移除；`异步加载点表` 语义变为"按当前机种快照装载"。

## 六、配置文件变更

| 文件 | 变更 |
|---|---|
| `config/recipes.json` | 结构改为 `{ 号, 名称, 区段快照 }`；旧的 `参数 / 启用面 / 示教点位项` 字段已移除（反序列化时被忽略，不会报错） |
| `config/parameters.json` | **新增**：`{ "当前参数": { 键: 值 } }` |
| `config/point-tables.json` | **删除**：点表数据整段属于机种，不再单独存文件 |
